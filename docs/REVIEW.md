# AI 코드 리뷰 가이드

## 리뷰 항목

### 1. 코드 가독성 및 유지보수성

- 변수명, 함수명, 클래스명이 역할을 명확히 표현하는가
- 중복 코드가 존재하는가
- 함수가 단일 책임 원칙(SRP)을 준수하는가
- 불필요하게 복잡한 로직이 존재하는가

### 2. 컨벤션 위반 여부

- 프로젝트 코딩 컨벤션 준수 여부
- 네이밍 규칙 준수 여부
- 패키지 구조 및 레이어 구조 적절성 확인
- 주석 작성 규칙 준수 여부

### 3. 모범 코드 제안

- 더 읽기 쉬운 코드 제안
- 성능 개선 가능한 코드 제안
- 최신 문법 또는 프로젝트 표준 패턴 제안
- 리팩토링 가능한 부분 제안

### 4. 논리적 오류 및 잠재적 버그 탐지

- NullPointerException 발생 가능성
- IndexOutOfBoundsException 발생 가능성
- Race Condition 가능성
- 무한 루프 가능성
- 예외 처리 누락 여부
- 비정상 입력 처리 여부

### 5. 테스트 관점 리뷰

- 단위 테스트 추가 필요 여부
- 테스트 누락 케이스 존재 여부
- 경계값(Boundary Value) 테스트 필요 여부
- 예외 상황 테스트 필요 여부

### 6. 보안 취약점 탐지

- 하드코딩된 비밀번호, API Key, Token 존재 여부
- SQL Injection 가능성
- XSS 취약점 가능성
- 인증/인가 누락 여부
- 개인정보 로그 출력 여부
- 민감정보 노출 가능성

### 7. 성능 검토

- 불필요한 DB 조회(N+1 문제)
- 불필요한 반복문
- 과도한 객체 생성
- 캐싱 적용 가능 여부
- 비효율적인 알고리즘 사용 여부

### 8. 아키텍처 및 설계 검토

- 레이어 책임 분리 적절성
- 의존성 방향 적절성
- 설계 원칙(SOLID) 위반 여부
- 확장성 및 유지보수성 고려 여부

### 9. 리뷰 결과 작성 규칙

- 문제 발견 시 이유를 설명한다.
- 개선 코드를 함께 제시한다.
- 심각도를 표시한다.
  - Critical
  - Major
  - Minor
  - Suggestion
- 문제가 없으면 "이상 없음"이라고 작성한다.

### 10. PR 리뷰 방식

- 변경된 파일만 리뷰한다.
- 변경 라인 기준으로 리뷰한다.
- 리뷰 댓글 형식으로 작성한다.
- 실제 PR 코멘트처럼 작성한다.
